# Qdrant indexing strategy

The collection is versioned as `company_documents_hybrid_v1`. Each PostgreSQL chunk maps to one Qdrant point using the chunk UUID, which is also persisted as `document_chunks.vector_id`.

## Vector indexes

- `dense`: 1536-dimensional cosine vectors generated by LangChain with `text-embedding-3-small`.
- `bm25`: sparse lexical vectors generated by FastEmbed's Qdrant BM25 model with Qdrant's IDF modifier.
- Dense vectors use HNSW (`m=16`, `ef_construct=128`). Retrieval uses `hnsw_ef=64`, which is a latency/recall compromise and should be tuned using production relevance data.
- Sparse postings remain in memory for low-latency lexical retrieval.

Hybrid queries retrieve 30 candidates independently from dense and sparse indexes. Qdrant applies reciprocal-rank fusion and returns the best five. Semantic-only queries bypass sparse retrieval and search the dense index directly.

## Payload indexes and authorization

Keyword indexes are created for `document_id`, `department`, `uploaded_by`, `channel`, and `thread`; `page` uses an integer index. Department and permission conditions are pushed into both hybrid prefetches, preventing unauthorized points from entering candidate sets or consuming reranking capacity.

The API derives permission filters from the authenticated user. Managers are restricted to their department; employees must appear in a point's `allowed_user_ids`; administrators are unrestricted. A manager-supplied department outside the manager's scope is rejected. PostgreSQL remains the source of truth, while Qdrant payloads provide retrieval-time enforcement and a PostgreSQL post-check closes synchronization windows.

## Latency considerations

- Async dense and sparse query embeddings run concurrently.
- Qdrant and embedding clients are reused between requests.
- Candidate retrieval is bounded, payloads are returned without vectors, and only five fused results leave Qdrant.
- Collections are versioned when embedding dimensions or sparse encoders change; upgrades should populate a new collection and switch configuration after validation.
